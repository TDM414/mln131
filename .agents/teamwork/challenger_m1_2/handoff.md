### 1.2 Direct Code Observations & Verbatim Errors

1. **Web Audio `exponentialRampToValueAtTime` Crash on `masterVolume = 0` (`src/lib/audioSynthesizer.ts`)**:
   - In `src/lib/audioSynthesizer.ts`, synthesis methods set initial gain by multiplying a constant by `this.masterVolume`:
     - Line 70: `gain.gain.setValueAtTime(0.28 * this.masterVolume, startTime);`
     - Line 71: `gain.gain.exponentialRampToValueAtTime(0.001, startTime + duration);`
     - Line 154: `gain.gain.setValueAtTime(isUrgent ? 0.35 * this.masterVolume : 0.25 * this.masterVolume, now);`
     - Line 155: `gain.gain.exponentialRampToValueAtTime(0.001, now + 0.045);`
     - Similar exponential ramps exist in `playSplat`, `playCorrectChime`, `playWrongBuzz`, `playSabotageStab`, and `startPartyBGM` (kick, snare, hat, bass).
   - **Verbatim Error**:
     When `masterVolume = 0` (e.g., if a teacher/host mutes sound via volume slider or sets volume to 0 instead of toggling the mute boolean), the starting gain is `0`.
     Under the W3C Web Audio API specification:
     `AudioParam.exponentialRampToValueAtTime(target, time)` throws:
     `RangeError: The float value provided must be greater than 0` (or `InvalidAccessError` when ramping from <= 0).
     Every sound effect and BGM step throws an unhandled `RangeError`!

2. **Unbounded Client Danmaku Burst Dispatch (`src/app/play/page.tsx:154-162` & `src/lib/syncEngine.ts:169`)**:
   - In `src/app/play/page.tsx:154`:
     ```ts

       if ('vibrate' in navigator) navigator.vibrate(35);
     ```

   - In `src/app/play/page.tsx:401-408`, the 6 reaction buttons (`🔥`, `🍅`, `🧱`, `❤️`, `🤡`, `🎦`) do NOT have `disabled` attributes or any cooldown lock.
   - When a user rapid-taps a reaction button (e.g. 20 taps in 1 second), all 20 calls immediately trigger `sync.sendDanmaku()`, dispatching 20 HTTP POST requests to `/api/game`.
   - On the server (`src/app/api/game/route.ts:562`), the ring buffer is capped at 120 events. Rapid Danmaku bursts from 2-3 spamming students flush legitimate game state events (`roast_submitted`, `phase_changed`) out of the buffer prematurely before slower mobile devices (700ms polling interval) can read them!
   - On the host screen (`src/app/host/page.tsx:125-127`), receiving `🍅` or `🧱` reactions triggers `sound.playSplat()`. In our test, 30 reaction bursts created 150 Web Audio nodes simultaneously on the host machine.

## 2. Logic Chain

1. **Audio Robustness Premise**: In classroom use, a teacher frequently adjusts the master volume slider or mutes sound during instructions by pulling volume to 0.
2. **Web Audio Constraint**: Setting `masterVolume = 0` produces starting values of `0` in `gain.gain.setValueAtTime(factor * masterVolume)`. Under W3C Web Audio standards, `AudioParam.exponentialRampToValueAtTime` cannot ramp to or from `<= 0`.
3. **Inference**: Calling any sound effect or starting BGM while `masterVolume = 0` causes an unhandled `RangeError` that crashes the audio playback logic.
4. **Danmaku Spammer Premise**: Classroom students naturally spam reaction buttons (especially tomatoes and bricks).
5. **Observation**: `play/page.tsx` lacks client-side button cooldowns, and `/api/game/route.ts` lacks per-player Danmaku throttling.
6. **Inference**: High-frequency Danmaku bursts overflow the server's 120-event buffer, causing slow-polling mobile clients to drop critical game show state updates, and spike audio node allocations on the host projector.
7. **Mobile Accessibility Premise**: Mobile inputs must remain accessible when virtual keyboards are displayed.
8. **Observation**: Root container uses `overflow-hidden` without an inner scroll wrapper.
9. **Inference**: On compact viewports (< 680px height), opening the software keyboard occludes the submit button and prevents the user from scrolling to complete the join flow.

## 4. Conclusion

**Verdict: REQUEST_CHANGES**

Milestone 1 has delivered high-quality foundational code, but 4 concrete, empirically reproducible defects must be addressed to ensure reliability in live classroom environments:

### Required Remediations:
1. **Fix Audio Zero-Volume Clamping in `src/lib/audioSynthesizer.ts`**:
   Clamp `masterVolume` before exponential ramps so it never passes `<= 0` to `exponentialRampToValueAtTime`. Use `Math.max(0.0001, this.masterVolume)` or add an early return `if (this.masterVolume <= 0) return;` at the top of sound synthesis methods.
2. **Add Client-Side Danmaku Cooldown in `src/app/play/page.tsx`**:
   Add a 400ms-600ms cooldown or throttle state on the Danmaku reaction buttons in `play/page.tsx` to prevent rapid burst spamming from flooding the server event buffer.
3. **Allow Vertical Scrolling on Mobile Join View (`src/app/play/page.tsx`)**:
   Replace `overflow-hidden` with `overflow-y-auto` or wrap the form in a scrollable container (`overflow-y-auto max-h-[calc(100dvh-80px)]`) so mobile users can scroll to the submit button when the virtual keyboard is open.
4. **Make SVG ClipPath ID Unique in `src/data/memeAvatars.tsx`**:
   Replace static `id="ref-clip"` in `VarInspectorSvg` with a unique ID (e.g. using `React.useId()` or `id={`ref-clip-${Math.random()}`}`) to eliminate DOM ID collisions in player rosters.
